# Повышения LONDO

Migration: `20260908090000_add_promotions`. Только новые таблицы и enum; применять через `npx prisma migrate deploy`. DATABASE_URL должен указывать на подтверждённую dev-базу atemii, не старую production DB. Не использовать db push/reset.

Модели: PromotionSettings, PromotionRank, PromotionCriterion, PromotionQuestion, PromotionApplication. Частичный unique index запрещает дубликаты PENDING/APPROVING. Ранги удаляются логически, заявки и снимки ответов/критериев сохраняются.

## Настройка

1. Перезапустить site и bot с актуальными файлами и сгенерированным Prisma client.
2. OWNER/FULL_ACCESS открывает `/promotions/admin`, выбирает MEMPHIS либо PHOENIX.
3. Настроить заголовок, описание, канал и включить приём. Для каждой семьи создать отдельные ранги/должности, выбрать Discord-роль, критерии, 1–5 вопросов SHORT/PARAGRAPH. Начальные ранги не предустановлены.
4. Большее значение порядка обозначает старший основной ранг. Должности не заменяют основные ранги. Одна Discord-роль принадлежит только одному зарегистрированному рангу; для независимых семейств используйте разные роли.
5. Сохранение обновляет панель. `/setup-promotions` повторно публикует/обновляет обе настроенные панели. Команда проверяет Discord Administrator либо текущие OWNER/FULL_ACCESS сайта.

Каналу нужны ViewChannel, SendMessages, ReadMessageHistory. Bot нужны ManageRoles и положение выше всех управляемых ролей. @everyone, managed, integration/bot и недоступные по иерархии роли исключаются. FAM и роли членства не могут быть целевыми. Служебные, общие legacy-роли и роли других семей никогда не снимаются. Для должности Recruit можно выбрать отдельную доступную роль; выдача должности не снимает основной ранг.

## Подача и рассмотрение

Discord: семья → активный ранг → критерии → «Подать заявку» → настроенная форма. Превью действует 15 минут; после изменения редактором форма должна быть открыта заново. Site повторно проверяет членство, состояние системы и ранга, Discord-роль, ответы и дубликаты. Ручные минимальные требования задаются обязательными критериями и проверяются reviewer по ответам; автоматическая проверка стажа/контрактов не подменяется вымышленными данными.

Страницы: `/memphis/promotions`, `/phoenix/promotions`, `/promotions/admin?family=MEMPHIS|PHOENIX`. Вкладки ожидающих/одобренных/отклонённых/истории/настроек; история загружается страницами по 200 записей, фильтры применяются к загруженным записям. Текущая политика applications разрешает управление только OWNER/FULL_ACCESS, а не HIGH_STAFF или RECRUIT.

При одобрении DB сохраняет APPROVING и план ролей до внешнего запроса. Bot сначала выдаёт целевую роль, затем снимает только разрешённые зарегистрированные основные ранги этой семьи, подтверждает состояние повторным fetch и завершает APPROVED. При сбое восстанавливает прежние ранги. Подтверждённый rollback возвращает PENDING; неоднозначный результат остаётся APPROVING, показывает ошибку и повторяется worker каждые 60 секунд. Нельзя менять ранги семьи во время APPROVING. При длительной ошибке проверить наличие участника, ролей и права bot; восстановить доступность и дождаться worker. Отклонение PENDING требует причину и не вызывает Discord role API.

GuildMemberUpdate и существующий member roster sync учитывают настроенные основные ранги. Статические старшие staff-ранги сохраняют приоритет; новая копия roster не создаётся.

## API и проверки

Site: `GET/POST /api/promotions/[family]` (повторный RBAC, проверка Origin для записи), `POST /api/internal/promotions` (shared secret).
Bot: `POST /internal/discord/promotions/options`, `/check`, `/apply`, `/refresh` (shared secret). Refresh принимает необязательную family. Apply принимает только applicationId и загружает сохранённый план с сайта.

Аудит: PROMOTION_APPLICATION_CREATED/APPROVED/REJECTED, ROLE_GRANTED, OLD_ROLE_REMOVED, RANK_CREATED/UPDATED/DISABLED, SETTINGS_UPDATED, PANEL_REFRESHED.

Проверки: обычные npm test/lint/tsc обоих проектов, npm run build сайта. `npx tsx scripts/promotions-integration.ts` создаёт отдельную временную PostgreSQL-схему и mock Discord API, запускает собранный сайт на 3197, проверяет HTTP/RBAC/CRUD/рассмотрение/историю и удаляет только свою временную схему. Порты 3197/3198 должны быть свободны. Настоящие Discord-роли тест не изменяет.
